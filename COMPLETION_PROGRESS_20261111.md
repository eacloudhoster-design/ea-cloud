Branch: `release/ea-cloud-integration-20261111`. Parent checkpoint: `ea4a42c7496e25ff1161956b3eaf25d05dfde28c`. Original archives and `RELEASE_*` verification documents are preserved unchanged. This continuation supersedes their source-completion status, not their historical evidence.

## Implemented in the existing release

- Opt-in live **read-only** identity verification across the private consumer, host driver, Windows launcher, SDK probe, root enrollment descriptor, relay and backend. SDK account mode, exact login/server, portable directory, disabled AutoTrading and credential proof remain mandatory. Backend `MT5_LIVE_READONLY_ACCOUNTS=1`, provisioner `allowLiveReadonly=true`, and host `allow_live_readonly=true` are separate explicit deployment decisions. Defaults remain false. No live execution path was enabled or inferred from these switches.
- Multiple owned account links, encrypted credentials, fresh per-account status, reconnection, disconnection, audit and explicit account selection in both shared master/follower UI and authenticated APIs. Up to 20 retained account links per owner; one account identity cannot belong to another tenant or role. Listing a saved account does not claim a current connection. A selection always pauses copying. Retained mappings, pending submissions and unbound successful legacy openings block switching the receiving binding. Disconnect retains credentials/evidence for reconciliation and does not claim to stop a terminal or close positions.
- Legacy connect paths honor the new ownership registry when enabled. The existing execution architecture still has **one selected receiving binding per client**; this is multiple-account management, not simultaneous execution on all linked accounts. Mentor source selection retains the existing 32-bit connection-schema limit. Simultaneous multiple receiving execution bindings and general live-order support are not implemented by this continuation.
- Full authenticated management startup (`pnpm --filter @workspace/api-server start:management`) sets `EA_MT5_MANAGEMENT_ONLY=1`, skips legacy schema/maintenance/queue reconciliation and execution-worker startup, and denies legacy/observer dispatch. It does not apply migrations or replace production services. Provisioning remains separately opt-in. Existing normal startup remains available and must not be used as a non-trading deployment command.
- Copying cannot be requested in management mode or without fresh worker permission, allocation, clear stops and journal evidence. Newly created settings default to paused. Dispatch rechecks the selected account/credential and copying permission. New observer mappings pin exact follower login/server; old unbound mappings are retained and fail closed until reconciliation. The reviewed migration adds nullable account identity columns without backfilling old mappings. The legacy copier download now requires an authenticated portal session; a fabricated bearer identity cannot export an API key.
- Dedicated-worker startup polls read-only readiness within a bounded deadline rather than failing on the first cold-start connection refusal. Private-driver budget is 90 seconds; consumer budget is 120 seconds. Uncertain allocations still cannot be replayed or recycled. Parent SIGKILL reconciliation remains an operator task.
- Pages optional management routing includes only the exact new owned-account and capability paths. Financial and authentication paths retain their existing destination. Any management override must share the original session/database bindings.
