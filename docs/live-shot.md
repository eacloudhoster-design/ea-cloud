# Live Shot — analysis only

Live Shot replaces the previously inactive **Live Chart** Settings entry. It is a lazy-loaded fullscreen market-analysis view. It has no order, copying, execution, account-modification or position-modification action.

## Architecture and licensing

TradingView **Lightweight Charts 5.2.1** (Apache-2.0) renders candles, scales, crosshair and touch/mouse navigation. Its library logo, visible TradingView creator/copyright attribution and a user-accessible licenses/notices link are retained. `public/licenses/` distributes the upstream Lightweight Charts NOTICE and Apache-2.0 license, plus Fancy Canvas MIT copyright/license. The restricted TradingView Advanced Charting Library is not needed. Lightweight Charts supplies no prices or AI: the feature obtains these separately. Risk/reward zones, price lines and draggable/keyboard-adjustable levels are EA Cloud overlays using the chart's price/logical coordinate transforms.

The existing secured HTTPS MT5 scanner bridge supplies exact broker symbol names (including suffixes), 400 OHLC candles and the bid quote. It supports M1/M5/M15/M30/H1/H4/D1. Live Shot does not call `symbol_select` or change Market Watch; if MT5 cannot supply history/ticks for an unselected symbol, make it available through the existing terminal procedure after approval. New Live Shot bridge reads reject a busy terminal immediately instead of queuing behind trading work. The existing MT5 terminal is still serialized: deployment needs a capacity/load check, and an in-progress read cannot be preempted. The browser polls every five seconds after each completed request, pauses requests while hidden, and aborts on selection changes/exit. It never substitutes generated prices. Quotes older than two minutes disable analysis. Candle history older than the selected interval plus a two-minute delivery tolerance also disables analysis; a fresh tick cannot make stale history current. MT5 does not supply a verified market-hours calendar here: status remains **unknown**, with freshness/connectivity shown separately. A verified closed flag disables analysis if provided. No claim of verified market-open status is made.

The existing scanner entitlement middleware protects every route under `/api/app/scanner/live-shot`. Analysis uses the existing configured Gemini model/key and provider transport, with a separate OHLC prompt/schema that permits **NO CLEAR SETUP**. It does not change the screenshot scanner prompt, reports or trading behavior. All input candles are fetched server-side from the connected account; a browser cannot submit replacement candles. Reports are validated for price ordering, finite values, supported ranges and evidence-backed nullable confidence. Supported patterns are described only when evidence permits.

A completed validated analysis consumes one existing scanner credit when the account has a finite credit allowance. It uses the same entitlement/client row locks as existing scanner completions. Failed/cancelled analysis rolls back. Live Shot reports are returned directly and do not alter the existing chart/fundamental history schema. Visual adjustments never create a server request or change the original report.

## Setup — no new paid service

Do not merge/deploy automatically. Review and approve all deployment changes first.

1. Deploy updated `vps-mt5-service/scanner_api.py` to the existing Windows MT5 service and restart it using its existing supervised procedure. This adds authenticated **read-only** `/scanner/symbols` and `/scanner/candles` routes; existing execution routes are unchanged. Verify the configured HTTPS reverse proxy allows those paths, keeps the bridge token server-side and does not log request bodies containing MT5 credentials. Python/MT5 terminal packages are already part of this service. Keep the VPS clock synchronized (UTC timestamps are validated).
2. The API continues using existing variable names: `SCANNER_MT5_VPS_URL`, `SCANNER_MT5_VPS_TOKEN`, `GEMINI_API_KEY`, and `GEMINI_SCANNER_MODEL` (or `GEMINI_MODEL`). Do not expose or replace their values. The client must already have an approved account, connected MT5 credentials and active scanner entitlement. No new provider subscription, database table, migration or secret is introduced.
3. Rebuild/redeploy the API with its existing Build/Start commands after approval. The documented repository-root Render build is `npx --yes pnpm@10.32.1 install --frozen-lockfile --prod=false && npx --yes pnpm@10.32.1 --filter @workspace/api-server build`; verify the dashboard still uses the existing documented configuration before deploying. New routes are mounted after the existing scanner access checks. No migration/start-command changes are required.
4. Build the frontend with the existing `pnpm run build:pages` command and deploy the normal combined Cloudflare Pages output after approval. A normal dependency installation resolves `lightweight-charts`/`fancy-canvas` from the committed package manifest/lockfile.
5. On an entitled test account, verify real suffixed symbols, candle timestamps/price precision, all seven timeframes, quote freshness and a successful provider response. Check a neutral/no-setup result and a justified setup, then chart pan/zoom/price scaling, local dragging and symbol/timeframe reset. Confirm no execution endpoints appear in the network log. Check iPhone Home Screen safe areas, chart-only pinch zoom, desktop, reconnect and exit/reopen.

If the bridge, terminal account or AI configuration is missing, the UI remains honestly unavailable. Installing the frontend alone will not create a market feed. Existing Gemini quota/billing applies; no new paid vendor has been added. Production settings, provider availability, costs and actual iPhone behavior have not been verified in this workspace.
